## 1. 评测集的设计与它的两次修正

### 1.1 设计约束

要回答的问题是「为了塞进 8GB 做的量化妥协，让模型变笨了多少」。这决定了两条
硬约束：

**必须能确定性打分。** 不用 LLM 当裁判——裁判本身也跑在这块 8GB 卡上，它的
误差会混进测量里，无法分辨是被测模型错了还是裁判错了。全部用选择题和极短
答案，字符串匹配判分。

**难度要铺开。** 全是简单题，q4 和 q8 都满分，看不出差异；全是难题，两个都
接近零分，同样看不出。目标是天花板落在 75–90 之间，留出下降空间。

最终构成：五个类别各 20 条，共 100 条。选择题 71 条，短答案 29 条。

### 1.2 第一次修正：答案键偏斜

用大模型批量生成的第一版有 105 条，其中 **93 条是 code 类**，其余四类只有
最初手写的种子各 3 条。更严重的是答案分布：

| | A | B | C | D |
|---|---|---|---|---|
| 修正前 | 26% | **62%** | 10% | 0% |
| 修正后 | 25% | 25% | 24% | 25% |

**一个永远输出 B 的模型原本能拿 58 分。** 那测的是猜测偏差，不是能力。

修正做法：保留 20 条 code 题（按答案键轮转挑选以分散分布），另外 80 条四类
手写，并对全部选择题旋转选项位置使正确答案均匀落在四个字母上。修正后全猜
同一字母只能拿 18 分。

同时修复了 16 条被 Markdown 破坏的题面（`__name__` 变成了 `**name**`），
删除了两对高度相似的重复题。

### 1.3 第二次修正：判分器在测自己

第一次跑基线得到 77/100，23 条错题。用 `lqb review` 逐条看模型的**原始回复**
（而不是只看题号），发现相当一部分不是模型错了：

| 题号 | 标准答案 | 模型回复 | 谁的问题 |
|---|---|---|---|
| arith-02 | `50` | `50dollars` | 判分器 |
| arith-09 | `150` | `150公里` | 判分器 |
| arith-16 | `4` | `4天` | 判分器 |
| arith-11 | `75` | `B`（即 125） | 模型 |
| arith-14 | `8` | `50` | 模型 |
| arith-15 | `16.7%` | `B`（即 25%） | 模型 |

短答案题要求数字，模型给出了带单位的正确数字却被判错。**人类读了会说它答对
了，那就是测量工具的缺陷。**

#### 判分规则的修改，以及为什么它不算「放宽」

加了一条严格限定的数值比较：

> 仅当预期答案是纯数字、**且模型回复中恰好只出现一个数字**时，按数值比较。

关键在「恰好一个」。验证过的行为：

| 预期 | 回复 | 判定 | 说明 |
|---|---|---|---|
| 150 | `150公里` | ✅ 对 | 忽略单位 |
| 50 | `50dollars` | ✅ 对 | 忽略单位 |
| 37 | `约 37 摄氏度` | ✅ 对 | 忽略前后缀 |
| 1081 | `1,081` | ✅ 对 | 忽略千位分隔符 |
| 75 | `125` | ❌ 错 | **数字不对，照样判错** |
| 8 | `36 - 28.26 = 7.74 = 8` | ❌ 错 | 含推导，四个数字，拒绝 |
| 150 | `可能是 150 或 200` | ❌ 错 | 含糊，两个数字，拒绝 |

它只忽略单位和语气词，不可能让含推导过程或含糊回答的蒙混过关。而且这条规则
对所有被测模型一视同仁，不会偏袒任何一方。

> **原则：改题目，不改判分逻辑。** 放宽匹配（比如允许包含关系）会让「我不确定，
> 可能是 150 或 200」也判对，后面所有模型的分数都会虚高，而且虚高程度还不
> 一样。判分器的严格性必须在被测对象之间保持一致。数值规则是个例外，因为它
> 是可精确定义、可验证、不引入模糊性的。

#### 同时修正了三条题目本身

| 题号 | 缺陷 | 处理 |
|---|---|---|
| cn-19 | 「画蛇添足」的四字解释不唯一（多此一举／弄巧成拙／徒劳无功都对） | 改成选择题 |
| arith-14 | 「保留整数」在四舍五入与截断之间有歧义（7.74 → 8 还是 7） | 改为「四舍五入到整数」 |
| fact-05 | 「每秒多少万公里」诱导「30万」或科学计数法 | 明确要求阿拉伯数字 |

**答案不唯一的题没法用短答案形式，只能改成选择题。** 这不是妥协，是承认短
答案的适用边界。

修正后重跑基线，77 → 81。**旧的 77 分作废**，判分规则和题面都变了。

## 3. 量化的代价：测不出来

q8_0 → q4_K_M：**总分从 81 降到 80**，差异集中在 code 一类（13 → 12），
其余四类完全相同。而逐题配对之后，连这 1 分也站不住。

### 配对检验：差异不存在

只看总分（81 vs 80）无法排除「两边各错了不同的题、恰好抵消」这种情况。用
`wrong_ids` 做逐题配对：

|  | q4 对 | q4 错 |
|---|---|---|
| **q8 对** | 79 | 2 |
| **q8 错** | 1 | 18 |

- **97/100 题两个模型判定完全相同**
- 不一致的只有 3 题：`reason-16`（q4 反而对）、`code-20` 与 `reason-14`
  （q4 错）
- **McNemar 精确检验双侧 p = 1.000**

这比「差异在噪声之内」强一个档次：不是测不出差异，而是配对之后差异本身不
存在。

作为对照，单次测量的标准误在 n = 100、p ≈ 0.81 时约 3.9 个百分点，95% 区间
约 ±7.7 pp。但配对设计不受这个限制——检验的功效取决于**不一致对的数量**，
而不是总题数。

### 那 18 条共同错题才是重点

两个模型错的是**同一批题**。这说明这些失败是 Qwen2.5-7B 本身的能力上限，
**量化没有引入任何新的失败模式**，只是在三道边缘题上换了一次运气。

如果量化真的在损伤模型，预期会看到 q4 在 q8 答对的题上成片失败。实际没有。

### 但省下的显存是实打实的

| | SIZE (ctx 4096) | GPU 驻留 |
|---|---|---|
| 7B q8_0 | 7.916 GiB | 66%（已卸载） |
| 7B q4_K_M | 4.586 GiB | 100% |

**省下 3.33 GiB。** 按 Day 4 实测的 128 KiB/token 换算，这些显存能买
**约 27000 tokens 的上下文**——足够把窗口从 4096 开到 26624 以上。

而且 q8_0 在 ctx 4096 下就已经卸载了 34%，意味着它不仅更占显存，还更慢。

> **一个预注册的预测**：Day 6 会实测 7B-q8 的吞吐。按 Day 4 的规律（卸载
> 34% 大约对应吞吐损失六成以上），预计落在 15–20 tok/s，约为 q4 的三分之一。
> 如果成立，结论就是「q8_0 用三倍的时间和 3.3 GiB 显存，换回统计上测不出来
> 的精度差异」。

## 4. 更大的模型：多 5 分，慢 6.16 倍

14B-q4_K_M 得 85 分，比 7B-q4 高 5 分。提升集中在 code（+3）、arithmetic
（+1）、reasoning（+1）——**全是需要多步推理的类别**，知识类（factual）和
语言类（chinese）一分未涨。

代价：

| | 解码速度 | 得分 |
|---|---|---|
| 7B-q4 ctx4096 | 51.98 tok/s | 80 |
| 14B-q4 ctx4096 | 8.44 tok/s | 85 |

**5 分换 6.16 倍的减速。** 在 14B 答完这 100 道题的时间里，7B-q4 可以答完
六遍。

### 一个重要的方法说明

14B 的精度是在**卸载 41.4% 的状态下**测的。这不影响比较的有效性——
**卸载改变的是速度，不是输出**。同样的权重、同样的 `temperature=0` 和
`seed=42`，无论层在 GPU 还是 CPU 上，生成的 token 序列是一样的。

所以「卸载惩罚速度，不惩罚质量」这句话，在这份数据里得到了支持。

## 5. 剩下的错题是真错

`lqb review` 显示 arithmetic 剩余三条失败全部是模型的真实能力缺陷：

- **arith-11**：「进货 200 本，卖出 62.5%，还剩多少」→ 答 125（卖出的数量）。
  读题错误，算对了但答错了问题。
- **arith-15**：「甲比乙多 20%，乙比甲少百分之几」→ 答 25%。典型的百分比
  反向错误，正确是 16.7%。
- **arith-14**：面积差 7.74 → 答 5。计算错误。

这三条正是评测集该保留的——它们区分得开模型能力。

## 6. 待补的分析

**样本量的边界。** 配对设计让 100 题比看上去更有力——检验功效取决于不一致
对的数量而非总题数，而 q8 与 q4 之间只有 3 对不一致。但反过来说，要在
p < 0.05 下检出任何差异，至少需要约 8 对不一致。**现在只有 3 对，所以这份
数据能支持的最强结论是「未发现差异」，而不是「已证明没有差异」。**

**14B 的比较未做配对。** 第 4 节那 5 分的差距只比了总分。理论上应该同样做
McNemar，但 14B 与 7B 是不同的模型而非同一模型的两种量化，配对的解释力弱
一些，且 5 分的差距方向明确、来源集中在三个推理类别，结论不依赖统计检验。
有余力可以补上。

**只测了一个上下文长度。** 全部精度评测在 `num_ctx=4096` 下进行。量化损失
是否随上下文增长而放大，本项目没有回答。这是一个自然的后续实验。

## 7. 对使用者的结论

在 8GB 消费级显卡上：

1. **用 q4_K_M，不要用 q8_0。** 100 题中 97 题判定相同，McNemar p = 1.000，
   精度差异不存在；而 q4 省下 3.33 GiB，够开约 27000 tokens 的上下文，
   并且不会卸载。
2. **省下的显存花在上下文上，不要花在更大的模型上。** 14B 多 5 分，慢
   6.16 倍。
3. **推理类任务是唯一可能值得上 14B 的场景**——提升全在 code / arithmetic /
   reasoning，知识类和语言类一分未涨。如果你的用途是问答或写作，7B 就够。
